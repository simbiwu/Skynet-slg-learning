# Skynet SLG 四课路线

四课沿用同一个 `~/workspace/skynet-slg-server` 工程。业务规模可控制在少量玩家、Region、兵种和玩法，但状态归属、持久化、并发、失败恢复、跨节点路由和线上验证不能靠教学捷径跳过。每课先完成一条玩家或运维人员能实际操作的链路，再按链路遇到的问题扩展架构；下面列出的能力域不等于开课时一次创建全部模块。

## 第一课：登录、双协议接入与进入世界

玩家先从 H5 或 Node 客户端发送 Login，收到玩家快照。内部链路从 Auth、PlayerMgr、PlayerAgent 和 Memory Storage 开始，随后接入 WebSocket：`8890` 使用 Protobuf Envelope 与 Body，`8891` 使用 8 字节应用 Header 与自定义二进制 Body。两个端口解析成同一内部请求，走同一个 Login 处理。Login 可用后再加 EnterWorld：WorldMgr 管理路由，RegionWorker 持有主城格子的权威状态；QueryWorld 用低频矩形查询观察结果。

第一课要能解释 fd 与逻辑连接的归属、连接 generation、跨 Service 调用的 yield、重复 EnterWorld 为什么不会创建第二座主城，以及协议错误如何回到客户端。真实 WebSocket E2E 覆盖两个端口。Memory Storage 只保留接口边界，进程退出后快照会丢失；此时不宣称已具备重启恢复。第一课不提前实现 Army、March、AOI 订阅或 Battle。

## 第二课：可恢复的世界行为

沿用第一课的世界和网络入口。先让玩家订阅一个视野范围，收到初始快照；对象变化后收到增量事件，再处理取消订阅、断线清理、批量推送和慢客户端背压。随后让玩家派出一支 Army：请求校验在 PlayerAgent 与 RegionWorker 的 Owner 边界内完成，路径和到达时间确定后保存 March，客户端能看到出发、途中、到达或召回结果。跨 Region 移交要明确旧 Owner 何时放弃、目标 Owner 何时接管，以及消息重复、失败和旧 generation 的处理。

第一次出现跨重启的长时间世界行为时，就把第一课的 Storage 边界接到 MySQL 等持久化实现，加入 Scheduler 的权威事件记录、到期触发和重启重建。保存顺序、版本、幂等键、旧 Timer 失效、进程崩溃后的恢复都随 March 一起设计，不把这些语义推迟到第四课。测试覆盖真实客户端行军、重复命令、重启中的 March 和跨 Region 失败；对 AOI 扇出与热点 Region 做定量观察。具体路径算法和地图规模可以简化，但应说明地形代价、缓存和负载变化时的替代方案。

## 第三课：多人冲突、战斗、领土与联盟

从两名玩家争夺同一格开始。攻击请求经已有网络入口进入目标 RegionWorker 的串行点；Battle 使用确定的输入、seed 和版本计算结果，生成可复查的战报。战斗结果改变 Army、城池或领土时，要定义跨 Player、Region、Territory Owner 的写入顺序、持久化边界和失败后的补偿或重试。之后加入领土连通、Alliance 成员与权限，以及多玩家 Rally 的最小完整状态机，并让客户端实际发起和观察这些行为。

验证重点是并发占格只能有一个最终结果、战斗可重放、重复结算不重复发奖、退盟和集结状态变化不会被旧回调覆盖。热点联盟和跨 Owner 同步链需要测量与审查；不靠单个全局 Manager 永久转发高频消息。

## 第四课：多节点、赛季与线上运行

把同一工程部署到多个 Skynet 进程或节点，让 Gateway、玩家和世界相关 Service 通过明确的路由与 `skynet.cluster` 协作。通过实际请求验证节点断开、重连、地址变化、超时、重复投递与恢复；跨节点调用不能假设与进程内调用有相同的失败表现。赛季部分完成世界创建、结算、归档与重置或迁移的最小闭环，明确哪些玩家数据保留、哪些世界数据清空，以及失败后如何继续。

用 Bot 持续制造登录、视野、行军、争地和联盟热点；记录队列长度、延迟分位数、CPU、Lua GC、网络和 DB 指标，结合 profiling 找到瓶颈。进行进程退出、数据库短暂不可用、消息延迟与重复等故障演练，留下复现步骤、日志关联信息、恢复结果和架构评审。Worker 数量、分片大小、AOI 推送策略和是否使用 C/C++ 扩展都根据负载数据讨论，不预设性能结论。

## 完成标准

四课结束时，学习者应能从一次客户端请求或一次线上故障，沿 Gateway、Service、Lua State、coroutine、状态 Owner、持久化和响应路径定位问题；能说明 Skynet 单 Service 内的 yield/reentrancy、跨 Region/节点移交、幂等与恢复、热点与扩容的设计取舍。仓库应有同一套可运行代码、必要的自动化测试、调试入口、负载数据和架构说明，足以展示与讨论成熟 SLG Server 的主要能力。课程不会声称这个有限玩法规模的工程已经是可直接上线的完整商业产品。
