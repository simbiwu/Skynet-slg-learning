# 测试与验证策略

统一测试入口为 `./scripts/linux/test.sh`。测试跟着实际行为增加，优先扩展已有套件；不为每个教学小节或 Service 单独建 Smoke Test。手工运行用于观察调用链，不能替代协议、状态、重启和并发验证。发现 Bug 时先补能复现问题的回归测试，再修复。

## 第一课：登录与进入世界

协议测试覆盖两个 WebSocket Binary 端口的编码、解码、版本、Flags、Command、畸形 Body、超长 Packet 和错误端口格式。真实客户端分别经 Protobuf 和自定义二进制端口完成 Login、EnterWorld、QueryWorld；跨端口重试 EnterWorld 仍返回同一座主城。错误 Token、越界坐标、Text Frame、旧连接 generation 和 RPC 期间 fd 关闭都应有明确结果。检查 Region 到 Worker 的路由、主城占格唯一性，以及调试入口能观察 PlayerAgent 和 RegionWorker。第一课 Memory Storage 不提供进程重启后的数据恢复。

## 第二课：视野、行军和重启恢复

真实客户端验证视野初始快照、增量事件、订阅变化、断线清理和慢客户端背压；验证行军出发、位置随时间推导、到达、召回、跨 Region 移交和重复请求。协议扩展仍覆盖两个端口。MySQL 等持久化集成测试要证明玩家、Army、March、Scheduler 事件在进程重启后恢复；同一到期事件重复投递或旧 Timer 触发不能重复结算。故障注入覆盖保存前后崩溃、目标 Region 暂时不可用和移交消息重复，检查对象不会消失或复制。对 AOI 扇出和热点 Region 测量队列、延迟和 CPU，记录负载条件。

## 第三课：多人冲突与联盟

并发占格测试应证明同一格只产生一个最终 Owner；固定输入、seed、版本的战斗可重放。重复结算、旧事件、跨 Owner 更新失败以及重启后继续处理，都要保持战报、领土和玩家收益一致。验证 Alliance 加入/退出与权限竞争，Rally 多参与者状态变化和旧回调失效。使用热点争地与联盟场景观察队列积压和同步调用链。

## 第四课：多节点、赛季与线上运行

在多 Skynet 节点的真实部署中验证路由、节点断开重连、超时、重复请求、旧地址和跨节点恢复。赛季结算、归档、重置或迁移要在中断后可继续，数据保留规则可检查。Bot 负载覆盖登录、视野、行军、争地和联盟热点，记录 p95/p99 延迟、队列长度、CPU、Lua GC、网络与 DB 负载；结合 profiling 说明瓶颈。进程退出、数据库短暂不可用和消息延迟等故障演练留下可复现步骤与恢复结果。性能结论只对记录的负载和部署条件成立。
